# Everloot 0.3.8: map positions, launch-day check

Addon 0.3.8 records places for the world map: the player's position while an NPC's window is open
(`npc_sighting` with `positionKind = "interaction"` and a `role`), and the player's position, a gather
kind and the object's name on an object's loot row. The beta closed before any of it ran in the Forever
client, so the event names, the interaction distance and the `UNIT_SPELLCAST_SENT` arguments are
unchecked. The code reads all of them defensively: an event that never fires, a call that is missing or
an argument of the wrong type records nothing and never errors. The automated tests
(`addon/tests/map_positions_contract.py`) use a mock shaped like Blizzard's documented signatures. This
list is the part only the live client can settle, on launch day (2026-11-04). Keep your SavedVariables
file before installing.

## What the code assumes

| Assumption | Used for | If it is wrong |
| --- | --- | --- |
| Events `MERCHANT_SHOW`, `GOSSIP_SHOW`, `QUEST_DETAIL`, `QUEST_GREETING`, `TRAINER_SHOW`, `TAXIMAP_OPENED`, `BANKFRAME_OPENED`, `AUCTION_HOUSE_SHOW`, `PET_STABLE_SHOW`, `CONFIRM_BINDER` | one interaction row per window | that window records no place |
| `PLAYER_INTERACTION_MANAGER_FRAME_SHOW` with an `Enum.PlayerInteractionType` value (`Merchant`, `Trainer`, `QuestGiver`, `TaxiNode`, `Banker`, `Auctioneer`, `StableMaster`, `Binder`, `Gossip`) | the same, on clients that moved to the interaction manager | that path records nothing; the old events above still do |
| `UnitGUID("npc")` names the NPC whose window is open (`"questnpc"` for quest windows) | which NPC the place belongs to | no row |
| The player is within a few yards of the NPC while its window is open | the place counts as the NPC's | pins sit off by that distance |
| `CanMerchantRepair()` | `repair` instead of `vendor` | repair NPCs show as vendors |
| `GetGossipOptions()` returning text, type pairs with `binder` for an innkeeper | `innkeeper` from a gossip window | innkeepers get a role only through `CONFIRM_BINDER` |
| `UNIT_SPELLCAST_SENT` sends unit, target, cast GUID, spell id (old clients: unit, spell, rank, target) | gather kind and object name | `gatherKind` is `other` or absent, no name |
| Gathering spell ids: Herb Gathering 2366, 2368, 3570, 11993; Mining 2575, 2576, 3564, 10248; Opening 3365, 6247, 6477, 6478, 21651, 22810; Fishing 7620, 7731, 7732, 18248 (and the same English names) | `herb`, `ore`, `chest`, `fishing` | that spell gives `other` |
| The loot window opens within 8 seconds of the cast being sent | linking the cast to the window | a slow cast gives no kind or name |

## In the client

1. Install the 0.3.8 zip, `/reload`, run `/everloot status`. Record the build and the addon version (0.3.8).
   The `openworld` line should end with `NPC windows`.
2. Run `/dump Enum.PlayerInteractionType` and copy the output. It says whether the interaction manager
   exists and which names it uses.
3. Open each NPC window once: a vendor, a vendor who repairs, a profession or class trainer, a quest giver
   (a quest you can accept, and an NPC with several quests for the greeting window), a flight master, a
   banker, an auctioneer, a stable master, an innkeeper (choose "Make this inn your home" and cancel), and an
   NPC with only gossip. Stand as far from the NPC as the game lets you open the window.
4. Log out and open the SavedVariables file. Expect one `npc_sighting` row per NPC with
   `positionKind = "interaction"` and the role from the table: `vendor`, `repair`, `trainer`, `questgiver`,
   `flightmaster`, `banker`, `auctioneer`, `stablemaster`, `innkeeper`, and no role for the gossip-only NPC.
   Write down which windows gave no row: their event name differs on Forever.
5. Compare one row's `x` and `y` with `/way` or a coordinate addon while standing on the NPC. Note the
   largest difference in map units: that is the interaction distance, and it should be well under 1.
6. Open the same vendor again, then the same vendor in a reload: no new row. A row for the same NPC appears
   again only in another zone.
7. Run `/eventtrace` (or `/etrace`), gather one herb, mine one vein and open one chest, and copy the
   `UNIT_SPELLCAST_SENT` lines: the argument order, the target text and the spell ids. Then cast one fishing
   line and loot it, and note whether the loot source is the bobber (object 35591) or a pool.
8. Log out. Expect each herb, ore and chest `loot` row to have `mapId`, `x`, `y`, the right `gatherKind` and
   the object's name as `sourceObjectName`. A creature's loot row has none of these. Any `gatherKind = "other"`
   on a herb, ore or chest means the spell id or name needs adding: copy it from step 7.
9. Open a profession trainer and confirm the new `trainer_seen` rows carry `trainerNpcId`, the trainer's NPC
   id.
10. Target an NPC: its row still says `positionKind = "player"`, and no pin may appear from it.
11. Upload from the website and from the Desktop App. Both must accept the rows (no invalid count in the
    preview or the app's result). A Desktop App built before protocol 1.9.0 marks interaction rows invalid
    and drops the loot positions: it needs a build with this change.

Report the windows that gave no row (step 4), the interaction distance (step 5), the spellcast lines and the
fishing source (step 7), and any `other` gather kind (step 8).
