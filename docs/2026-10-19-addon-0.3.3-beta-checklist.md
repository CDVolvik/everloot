# Everloot 0.3.3: completion tracker beta check

Addon 0.3.3 adds a completion module: achievements, reputation, titles and quest chains. It is off until
you run `/everloot completion on`. It only reads; it never spends, tracks, expands a window or acts for
you. The automated tests use a mock shaped like the calls below. This list is the part only the game
client can settle. Keep your SavedVariables file before installing.

## What the build's own files say

Checked on build 1.60.1.70450 (product `wow_classic_beta`), read from Blizzard's CDN by file name: the
generated API documentation (`Blizzard_APIDocumentationGenerated`, 642 files) and the Lua of the
achievement, Legacy System, reputation and character windows.

Forever's tables of contents name its game type `camelot`. Three things follow.

- **Achievements are shown as Legacy Challenges.** The camelot override of the achievement window
  (`Blizzard_AchievementUI/Camelot`) opens the Legacy Challenges window instead of the achievement
  frame, zeroes the achievement summary and gates it on a game rule and on legacy renown. The achievement
  globals are still what that window calls, so the module reads them. The catalog it records is the list
  the game gives these calls, which may be only the legacy subset. Step 4 below finds out how many.
- **Reputation is the modern `C_Reputation` list.** Forever's own reputation frame
  (`Blizzard_UIPanels_Game/Camelot/ReputationFrame.lua`) uses `GetNumFactions` and `GetFactionDataByIndex`.
  The old global `GetFactionInfo` is not in the documentation or in the window code, so there is no
  fallback to it. The list is the rows the window currently shows: a collapsed header hides its
  factions, and the module never expands one for you.
- **Titles and quests** use calls that are in the documentation, and Forever's character frame uses the
  title calls.

| Call | In the generated API documentation | Used by Blizzard's own window code in this build |
| --- | --- | --- |
| `GetCategoryList`, `GetCategoryInfo`, `GetCategoryNumAchievements`, `GetAchievementInfo` | no (global functions) | yes (Legacy Challenges window, achievement window) |
| `GetAchievementNumCriteria`, `GetAchievementCriteriaInfo` | no (global functions) | yes (Legacy Challenges window, achievement window) |
| `C_AchievementInfo` (`IsValidAchievement`, `IsGuildAchievement`, ...) | yes | yes; the module does not call it |
| `C_Reputation.GetNumFactions`, `GetFactionDataByIndex` | yes | yes (camelot reputation frame) |
| `C_Reputation.IsMajorFaction` | yes | yes (camelot reputation frame) |
| `GetNumTitles`, `GetTitleName`, `IsTitleKnown` | yes | yes (camelot character frame) |
| `C_QuestLog.GetAllCompletedQuestIDs` | yes | not seen in the files read |
| `C_QuestLine.GetQuestLineInfo`, `GetQuestLineQuests` | yes | not seen in the files read |
| `C_Timer.After` | yes | not checked in the files read |
| events `ACHIEVEMENT_EARNED`, `QUEST_TURNED_IN`, `UPDATE_FACTION`, `FACTION_STANDING_CHANGED`, `KNOWN_TITLES_UPDATE` | yes | n/a |

Signatures the code follows: `GetAchievementInfo` returns id, name, points, completed, month, day, year,
description, flags, icon, reward text, is-guild, earned-by-me (the Legacy window reads the thirteenth
value to decide whether the character earned it). `GetAchievementCriteriaInfo` returns the criteria
text, type, completed, quantity, required quantity. `FactionData` has `factionID`, `name`, `reaction`,
`currentReactionThreshold`, `nextReactionThreshold`, `currentStanding`, `isHeader`, `isHeaderWithRep`,
`isChild`, `isCollapsed`. A call missing from the documentation can still exist; one present there can
still return nothing for a Forever character, so the steps below check each.

## What is recorded

Catalog rows hold game facts only: ids, names, criteria text, standing headers, quest ids. They carry
no player data and are listed on the site after three installs report the same entry.
Owned rows are your character's progress, under an 8-digit key made from your install id and the
character's GUID. The key is not the name. They are listed on the site only when you upload with the
"My collection ownership and completion progress" choice ticked and a verified grant, like
`collection_owned`. A changed achievement or standing replaces its earlier row in your file, so the file
does not grow with every point of reputation. Titles and completed quests are written as additions.

## In the client

1. Install the 0.3.3 zip over the old one, `/reload`, run `/everloot status`. Record the build (expected
   1.60.1.70450) and the addon version (0.3.3). The `completion` line should say `off by toggle`.
2. Run `/everloot completion on`, then `/reload`, then `/everloot status`. The `completion` line should
   list achievements, reputation, titles and quests each as `ready`. A `missing ...` name is a call this
   client does not have: copy the line. That part records nothing until it does.
3. Run these and copy the chat output (pick a category id from the first, and a quest id you completed):
   `/dump GetCategoryList()`, `/dump GetAchievementInfo(<category id>, 1)`, `/dump GetAchievementCriteriaInfo(<achievement id>, 1)`,
   `/dump C_Reputation.GetFactionDataByIndex(1)`, `/dump GetNumTitles(), GetTitleName(1), IsTitleKnown(1)`,
   `/dump #C_QuestLog.GetAllCompletedQuestIDs()`, `/dump C_QuestLine.GetQuestLineInfo(<quest id>)`,
   `/dump MAX_REPUTATION_REACTION`. The module expects the shapes in the table above and a top standing of 8.
   If `GetTitleName` returns nothing for a title you do not have, the title catalog only lists titles you
   know; that is fine, other installs fill the rest.
4. Run `/everloot completion`. The game must stay smooth while it reads (the read is chunked across
   frames and waits out combat). When it finishes, `/everloot status` shows how many achievements,
   factions and titles were read, how many quests were newly completed and how many chains were found.
   Write down the achievement count: it says how much of the catalog Forever gives these calls. If it says
   `paused at capacity` or `stopped at 3000`, report that.
5. Open the reputation window. If the status line said some headers are collapsed, expand them and run
   `/everloot completion` again; the faction count should grow.
6. Log out and open the SavedVariables file. Compare by hand with what the game shows: two achievements
   (one complete with its date, one part done with the criteria met out of the total), two reputations
   (the standing name, the standing value and the next threshold), the titles you know, and one quest chain.
   An achievement complete on the account but not earned by this character should read
   `completed = true, earnedByMe = false`.
7. Turn in a quest, gain some reputation, then wait about 15 seconds and run `/everloot status`. Expect a
   new `quest_owned` row with only the new quest id, and the reputation row replaced: the count of
   `reputation_owned` rows does not rise.
8. Log in a second character. Expect a different `characterKey`, no repeated catalog rows, and no
   character name anywhere in the file.
9. Start `/everloot completion` and enter combat. Expect the read to wait until combat ends.
10. Run `/everloot completion off`. Every completion row is deleted from the file; `/everloot status`
    shows zero for the eight kinds.
11. Turn it on again, read, log out, and preview the file at `/upload`. The completion owned rows are held
    unless you tick the collection choice; the catalog rows are listed under their own kinds. Check that
    nothing there is a name.

Report any `missing ...` name from step 2, any dump from step 3 that differs from the table, the
achievement count from step 4, and any value in step 6 that differs from the window.
