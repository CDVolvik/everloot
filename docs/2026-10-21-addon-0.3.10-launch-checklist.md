# Everloot 0.3.10: map positions, launch-day check

Addon 0.3.10 records places for the world map: the player's position while an NPC's window is open
(`npc_sighting` with `positionKind = "interaction"` and a `role`), and the player's position, a gather
kind and the object's name on an object's loot row. It also records what the site took only from Polestar
Recorder files until now: a rare's own position from the minimap's vignette (`npc_sighting` with
`positionKind = "vignette"`), a treasure's (`object_sighting`), the dungeon or raid the player zoned into
with the outdoor position (`instance_entrance`) and a boss fight's end (`encounter`). The beta closed before any of it ran in the Forever
client, so the event names, the interaction distance, the `UNIT_SPELLCAST_SENT` and `ENCOUNTER_END`
arguments and the vignette calls are unchecked. The code reads all of them defensively: an event that never fires, a call that is missing or
an argument of the wrong type records nothing and never errors. The automated tests
(`addon/tests/map_positions_contract.py`) use a mock shaped like Blizzard's documented signatures. This
list is the part only the live client can settle, on launch day (2026-11-04). Keep your SavedVariables
file before installing.

## What the code assumes

| Assumption | Used for | If it is wrong |
| --- | --- | --- |
| Events `MERCHANT_SHOW`, `GOSSIP_SHOW`, `QUEST_DETAIL`, `QUEST_GREETING`, `TRAINER_SHOW`, `TAXIMAP_OPENED`, `BANKFRAME_OPENED`, `AUCTION_HOUSE_SHOW`, `PET_STABLE_SHOW`, `CONFIRM_BINDER` | one interaction row per window | that window records no place |
| `PLAYER_INTERACTION_MANAGER_FRAME_SHOW` with an `Enum.PlayerInteractionType` value (`Merchant`, `Trainer`, `QuestGiver`, `TaxiNode`, `Banker`, `Auctioneer`, `StableMaster`, `Binder`, `Gossip`) | the same, on clients that moved to the interaction manager | that path records nothing; the old events above still do |
| `UnitGUID("npc")` names the NPC whose window is open (`"questnpc"` for quest windows) | which NPC the place belongs to | no row |
| The player is within a few yards of the NPC while its window is open | the place counts as the NPC's | pins sit off by that distance |
| `CanMerchantRepair()` | `repair` instead of `vendor` | repair NPCs show as vendors |
| `GetGossipOptions()` returning text, type pairs with `binder` for an innkeeper | `innkeeper` from a gossip window | innkeepers get a role only through `CONFIRM_BINDER` |
| `UNIT_SPELLCAST_SENT` sends unit, target, cast GUID, spell id (old clients: unit, spell, rank, target) | gather kind and object name | `gatherKind` is `other` or absent, no name |
| Gathering spell ids: Herb Gathering 2366, 2368, 3570, 11993; Mining 2575, 2576, 3564, 10248; Opening 3365, 6247, 6477, 6478, 21651, 22810; Fishing 7620, 7731, 7732, 18248 (and the same English names) | `herb`, `ore`, `chest`, `fishing` | that spell gives `other` |
| The loot window opens within 8 seconds of the cast being sent, 30 for fishing | linking the cast to the window | a slow cast gives no kind or name |
| Only herb, ore and chest casts keep their target as the object's name | no player name reaches a loot row | objects opened by other spells stay unnamed |
| `C_VignetteInfo.GetVignettes`, `GetVignetteInfo` and `GetVignettePosition(vignetteGUID, uiMapID)` exist on Forever (the API docs list them for 1.60.1) | rares and treasures at their own position | no vignette row |
| Events `VIGNETTE_MINIMAP_UPDATED` (vignetteGUID, onMinimap) and `VIGNETTES_UPDATED` fire on Forever | when a vignette is read | no vignette row, or only when the other event fires |
| Forever shows rares and treasures as vignettes at all, and a vignette's `objectGUID` is the rare's `Creature-` or the treasure's `GameObject-` GUID | which NPC or object the row is | no row, or (if a vignette names something else) a wrong id |
| `GetVignettePosition` returns a table with `x`, `y` from 0 to 1 on the player's `C_Map.GetBestMapForUnit` map | the rare's or treasure's own place | no row (a value outside 0..1 is refused) |
| `info.name` is the rare's or the object's name, not a label such as "Rare" | the row's name | names are wrong; the site shows a name only when 3 installs agree |
| `PLAYER_LEAVING_WORLD` fires as the loading screen into an instance starts, while `C_Map.GetPlayerMapPosition` still gives the outdoor position | the entrance's place | no entrance row, or a place that is not the portal |
| `GetInstanceInfo` returns the instance type (`party`, `raid`) and the map id 8th, and a dungeon finder id 10th that is nil or 0 outside the dungeon finder | the entrance's instance; dungeon finder teleports left out | no row, or a teleport's start recorded as an entrance |
| Being summoned into an instance (a warlock or a meeting stone) is rare | the entrance's place | a summon records where the player stood when summoned; the site needs 3 installs on one map before it uses an entrance |
| `ENCOUNTER_END` sends encounterID, encounterName, difficultyID, groupSize, success (1 or 0) | the encounter row | no encounter row |
| `ENCOUNTER_END`'s 6th argument, the boss units with `creatureID` (added in 12.0.7 per the docs), may be absent on Forever | `npcIds` | encounter rows carry no boss ids |

## In the client

1. Install the 0.3.10 zip, `/reload`, run `/everloot status`. Record the build and the addon version (0.3.10).
   The `openworld` line should end with `NPC windows`.
2. Run `/dump Enum.PlayerInteractionType` and copy the output. It says whether the interaction manager
   exists and which names it uses.
3. Open each NPC window once: a vendor, a vendor who repairs, a profession or class trainer, a quest giver
   (a quest you can accept, and an NPC with several quests for the greeting window), a flight master, a
   banker, an auctioneer, a stable master, an innkeeper (choose "Make this inn your home" and cancel), and an
   NPC with only gossip. Stand as far from the NPC as the game lets you open the window.
4. Log out and open the SavedVariables file. Expect one `npc_sighting` row per NPC with
   `positionKind = "interaction"` and the role from the table: `vendor`, `repair`, `trainer`, `questgiver`,
   `flightmaster`, `banker`, `auctioneer`, `stablemaster`, `innkeeper`, and no role for the gossip-only NPC.
   Write down which windows gave no row: their event name differs on Forever.
5. Compare one row's `x` and `y` with `/way` or a coordinate addon while standing on the NPC. Note the
   largest difference in map units: that is the interaction distance, and it should be well under 1.
6. Open the same vendor again, then the same vendor in a reload: no new row. A row for the same NPC appears
   again only in another zone.
7. Run `/eventtrace` (or `/etrace`), gather one herb, mine one vein and open one chest, and copy the
   `UNIT_SPELLCAST_SENT` lines: the argument order, the target text and the spell ids. Then cast one fishing
   line and loot it, and note whether the loot source is the bobber (object 35591) or a pool.
8. Log out. Expect each herb, ore and chest `loot` row to have `mapId`, `x`, `y`, the right `gatherKind` and
   the object's name as `sourceObjectName`. A creature's loot row has none of these. Any `gatherKind = "other"`
   on a herb, ore or chest means the spell id or name needs adding: copy it from step 7.
9. Open a profession trainer and confirm the new `trainer_seen` rows carry `trainerNpcId`, the trainer's NPC
   id.
10. Target an NPC: its row still says `positionKind = "player"`, and no pin may appear from it.
11. Heal or buff another player, then open a chest without a cast (or within a few seconds): the loot row
    must not carry that player's name.
12. Run `/dump C_VignetteInfo` and `/dump GetInstanceInfo()` outdoors, and copy the output: whether the
    vignette API exists, and the ten returns outdoors. Then stand near a rare or a treasure the minimap marks
    and run `/dump C_VignetteInfo.GetVignettes()`, then `/dump C_VignetteInfo.GetVignetteInfo("<a GUID from
    that list>")` and `/dump C_VignetteInfo.GetVignettePosition("<that GUID>", C_Map.GetBestMapForUnit("player"))`.
    Note the `objectGUID`, the `name` and the position. If the minimap marks nothing, Forever has no
    vignettes and step 13's rows cannot appear.
13. With `/eventtrace` open, walk up to a rare or a treasure the minimap marks, and note which of
    `VIGNETTE_MINIMAP_UPDATED` and `VIGNETTES_UPDATED` fire. Log out: expect an `npc_sighting` with
    `positionKind = "vignette"` for the rare, or an `object_sighting` for the treasure, at the rare's or the
    chest's own spot (check with `/way` standing on it; it should match within 1), not where you stood.
14. Walk into a dungeon portal, then a raid portal if one is near. In each, run `/dump GetInstanceInfo()` and
    copy the ten returns (the 8th is the map id, the 10th the dungeon finder id). With `/eventtrace` open,
    note whether `PLAYER_LEAVING_WORLD` fires before the loading screen. Log out: expect one
    `instance_entrance` per instance with `instanceType`, `difficulty` and an outdoor `mapId`, `x`, `y` at the
    portal (compare with `/way` at the portal). Walk out and back in: no second row. `/reload` inside: no row.
15. Kill a dungeon boss, and wipe on one if you can. Copy the `ENCOUNTER_END` line from `/eventtrace`: the
    arguments and whether a 6th (the boss units) is there. Log out: expect an `encounter` row with
    `success = true` for the kill and `false` for the wipe, `difficulty`, `size`, and `npcIds` only if the 6th
    argument came.
16. Update the Desktop App to a build with protocol 1.10.0 or later before uploading, and to one with
    protocol package 1.12.0 (record protocol 1.7.0) or later for the vignette, entrance and encounter rows;
    the first Desktop App build that carries 1.12.0 is [?]. An older build marks
    interaction rows invalid (they stay unsent, so the updated app sends them) and drops the loot positions
    (the site keeps the fuller copy if the same event arrives again with them).
17. Upload from the website and from the updated Desktop App. Both must accept the rows (no invalid count in
    the preview or the app's result).

Report the windows that gave no row (step 4), the interaction distance (step 5), the spellcast lines and the
fishing source (step 7), any `other` gather kind (step 8), the vignette dumps and events (steps 12 and 13), the
`GetInstanceInfo` returns and whether `PLAYER_LEAVING_WORLD` fired (step 14), and the `ENCOUNTER_END` line (step 15).
