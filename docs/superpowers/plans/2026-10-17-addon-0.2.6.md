# Plan: addon 0.2.6 (installed addons, zone bounds, client build)

**Spec:** `docs/superpowers/specs/2026-10-17-addon-0.2.6-addons-and-map-bounds-design.md` (branch
`docs/specs-2026-10-17`), plus row E and Phase 1b of the architecture audit (`clientBuild` on uploads).
**Out of scope:** the `/addons/popular` page and the world map. They come after the site restyle.

Each task is test-first: the test fails, then the change makes it pass.

## 1. Intake contract (`web/src/lib/intake.ts`)

- `addon_seen`: `name` (folder), `title`, optional `version`, `loaded`.
- `map_bounds`: `mapId`, `continentId`, `left`, `top`, `right`, `bottom`; width and height not zero.
- Both in `recordSchemas`, the union and `ALL_RECORD_KINDS` (19 → 21).
- Envelope: optional `clientBuild` (digits and dots, like `1.60.1.70450`); `CanonicalUpload` keeps
  it, so the stored upload object records the build. A 0.2.5 upload without it still parses.
- Tests: `web/src/lib/intake.test.ts`; the every-kind fixture in `kb/test/tool-kinds.test.ts`.

## 2. Upload path carries the build and shows the addon list

- `web/src/lib/sv-parse.ts`: read `EverlootDB.clientBuild` when present.
- `web/src/lib/upload-batches.ts`: put `clientBuild` in each batch envelope; collect the addon
  titles being sent so the preview can list them.
- `web/src/app/upload/UploadClient.tsx`: pass `clientBuild`; list the addons in the preview.
- `companion/src/uploader.ts`: pass `clientBuild`.
- Tests: `sv-parse.test.ts`, `upload-batches.test.ts`, `companion/test/uploader.test.ts`.

## 3. kb rollups

- `kb/src/addon-rollup.ts`: per addon, installs that reported it, installs that had it loaded,
  share of reporting installs, first and last seen; public at three installs; Everloot and
  EverlootAnswers left out. No install id in the output.
- `kb/src/map-bounds.ts`: per zone, each install's newest report; bounds are agreed once three
  installs match (the data policy's rule) within one world unit on every edge and on the continent.
- Tests: `kb/test/addon-rollup.test.ts`, `kb/test/map-bounds.test.ts`.

## 4. Addon

- `core.lua`: 0.2.6; `clientBuild` from `GetBuildInfo()`; new toggles default from `defaults`
  for existing files (so `addons` starts off for players upgrading from 0.2.5);
  `/everloot addons on|off`; new kinds in `/everloot status`.
- `modules/addons.lua`: off by default; `C_AddOns` or the legacy globals, disabled if neither;
  at `PLAYER_LOGIN`, a row when an addon is new or its version or loaded state changes, plus one
  check-in a week. Sent only from the upload page; the companion and the public corpus leave it out.
- `modules/mapbounds.lua`: on zone entry, `C_Map.GetWorldPosFromMapPos` at (0,0) and (1,1),
  once per zone per client build. Every Blizzard call guarded.
- `Everloot.toc`: 0.2.6, `## X-License: AGPL-3.0`, both modules.
- Tests: `addon/tests/addons_contract.py`, `addon/tests/mapbounds_contract.py`, added to CI and
  `addon/README.md`.
- Rebuild `web/public/downloads/Everloot-0.2.6.zip`.

## 5. Docs

- `addon/README.md`: status 0.2.6, new modules and toggle.
- `docs/DATA_POLICY.md`: the addon list is recorded only when the player turns it on.
- `docs/2026-10-08-beta-client-checklist.md`: in-client checks for the two modules and the build.
