# Addon 0.2.6: installed addons and zone bounds

**Date:** 2026-10-17
**Status:** design for Carlos's review.
**Serves:** the Forever addon leaderboard (this spec) and the world map
(`2026-10-17-world-map-design.md`).

## Why

Two things nobody else publishes for WoW: Forever, which Everloot can collect within the rules:

1. **Which addons Forever players actually run.** CurseForge's API terms forbid saving or caching
   its data and building anything that competes with it (3rd Party API Terms, section 3.1), so a
   leaderboard cannot come from CurseForge. It can come from our own players, with their consent.
2. **Where each zone sits in the world.** The site's spawn pins are zone coordinates (0 to 1). To
   draw one continuous world map, the site needs each zone's rectangle in world coordinates. The
   game hands this to any addon through `C_Map`; nobody publishes it as data.

## What the addon records

Two new record kinds, both through the existing intake contract (`web/src/lib/intake.ts`):

| Kind | Fields | When |
|---|---|---|
| `addon_seen` | `name` (folder name), `title`, `version` (from the `.toc`), `loaded` (bool) | Once per session per addon, at `PLAYER_LOGIN`, only when the player turned it on |
| `map_bounds` | `mapId`, `continentId`, `left`, `top`, `right`, `bottom` (world units) | Once per zone the player enters, if not already recorded for this build |

- **Consent:** `addon_seen` is off by default. `/everloot addons on` turns it on; `/everloot status`
  shows its state. The upload preview lists the addons before anything is sent.
- **API:** `GetNumAddOns`/`GetAddOnInfo`/`GetAddOnMetadata` (or their `C_AddOns` versions,
  whichever the Forever client has; the module checks at load and disables itself if neither
  exists). `C_Map.GetWorldPosFromMapPos(mapId, {0,0})` and `{1,1}` give a zone's corners.
- **Nothing else:** no addon settings, no SavedVariables of other addons, no character data.

## What the site publishes

- **Forever addon leaderboard** at `/addons/popular`: addon title, how many installs reported it,
  first and last seen dates, the share of reporting installs that run it, and a link to search
  for it on CurseForge (link only). An addon appears once at least three installs report it.
  Everloot itself is excluded from the ranking.
- **Zone bounds** feed the world map; a zone's bounds are used once two installs agree to within
  one world unit (bounds are exact game data, so honest reports match).
- The public corpus serves these records like the others: without the install id.

## Contract changes

- `web/src/lib/intake.ts`: two schemas; `ALL_RECORD_KINDS` gains both.
- `kb/src/`: `addon-rollup.ts` (counts per addon, three-install rule) and `map-bounds.ts`
  (agreement rule), each with tests in the style of `drop-rollup.ts`.
- Addon: `modules/addons.lua` and `modules/mapbounds.lua`, contract tests
  `addon/tests/addons_contract.py` and `addon/tests/mapbounds_contract.py`.
- Version 0.2.6 in `Everloot.toc` (with `## X-License: AGPL-3.0`, starter issue #5) and `core.lua`;
  the zip is rebuilt.

## Risks

- The Forever beta closes 10/21. Without an in-client check, 0.2.6 ships with the same "automated
  checks only" label as 0.2.5. Every Blizzard call stays guarded.
- Addon names can identify rare setups. Only counts at three or more installs are shown.

## Out of scope

CurseForge API use of any kind; ranking by downloads; addon settings or versions beyond the `.toc`.
